# 回退机制 — 设计（0.1.13，2026-10-26）

> 本文是私有源码库里同名设计文档的公开版：内容相同，去掉了本机路径和内部审计 / 实验文件的位置。文中的源码文件名指私有仓库里的位置。

用户的要求：左上角一个万能返回键，Esc 也能回退；跳转页面或任何逻辑上说得过去的操作都可以回退，但要甄别不可回退的情况（模型创建好点了保存、密钥点了保存，这些不能"回退"）；从最保守的开始——**页面级回退**：进入拆件模块后，回退应回到上一个页面。要求万分严谨。

## 1. 现状（2026-10-26 调研，细节见代码引用）

- 路由：react-router 7 的 `createHashRouter`（`#/home`、`#/workspace?asset=…&module=…`），用的就是窗口自己的 history（pushState / replaceState / popstate），`history.state.idx` 是栈内序号（`routes.tsx`、`App.tsx`）。
- 什么进历史栈：顶栏导航、`navigate(path)`（约 30 处）默认 **push**；同一地址的 Link 自动 replace（react-router 的 Link 行为）——但只在路径**和参数**都相同时：工作台 URL 带着 `?asset=…&module=…` 时再点「工作台」页签会 push 一条新记录（真机第一次核对就撞上：回退回到的是上一条工作台记录而不是首页）。0.1.13 起顶栏页签、设置按钮、Ctrl+数字指向当前页面时一律 replace。
- 什么不进栈（全是 **replace**）：工作台的模块切换、选资产 / 选版本（`useWorkspaceLocation` 默认 replace）、资产页的详情抽屉（`?asset=`）、设置分区、引擎视图、三处重定向（首页、首次运行转引导、路由错误重试）。
- Esc 现状：没有中央注册表。Radix 层（对话框、确认框、菜单、下拉、提示）在 document 捕获阶段处理 Esc 并 `preventDefault`；任务抽屉焦点在外时 `preventDefault` 且不关闭（有测试断言）；资产页 `useHotkey('escape')` 关抽屉或清选择；十来处行内编辑用 Esc 撤销草稿（多数 `stopPropagation`）。`useHotkey` 会跳过：输入法组合中、自动重复、`defaultPrevented`、焦点在可编辑元素（无修饰键时）、有模态层打开（body 的 pointer-events 为 none）。
- 主进程：没有处理 `app-command`（鼠标侧键）、没有 goBack；生产环境没有菜单，Alt 无作用。
- 顶栏：整条是拖拽区（`app-drag`），可点控件要 `app-no-drag`。
- 已有的"放弃？"确认：图片编辑器有修改时关闭、概念图请求进行中关闭（都是模态对话框内部的事）。没有路由离开守卫（无 useBlocker、无 beforeunload）。
- 没有守卫的本地草稿：动作映射 `mappingDirty`、密钥输入框里敲了还没保存的内容。生成面板的草稿在 store 里，离开不丢。

## 2. 定义：回退回的是什么

**回退 = 回到历史栈里的上一个页面地址**，仅此而已。它改变的只有"现在看哪一页"，从不改变任何数据：

- 已提交的事情（生成任务、保存的密钥、保存的方案、导入的资产、发送到 Unity……）都在主进程落了盘，回退不碰它们——这是"不可回退的情况"的统一答案：**凡是经过 IPC 提交的都不在回退的范围内**，没有例外，也不需要逐个判断。
- 页内选择（工作台的模块、资产、版本；资产页的抽屉；设置分区）是 replace，回退不在它们之间来回；从工作台的拆件模块回退，回到进入工作台之前的那一页（首页 / 资产 / 设置……），正是用户要的"回到上个页面"。
- 回退只在"回得去"时可用：`history.state.idx > 0`（首次进入的那一页是栈底，按钮灰掉、Esc 无动作）。
- **外来的历史条目**（不是路由器写的，比如直接给 `location.hash` 赋值：端到端夹具离开引导页就是这么做的；应用里曾有一处——没挂在路由树下的图片编辑器的「去设置」链接，已改走路由器）没有序号：路由器既不知道它前面有没有东西，也拦不住"回到它"的 popstate（拦截要靠序号差来恢复位置）。第一次真实运行就撞上了：密钥草稿的离开守卫没有弹出，页面直接回到了首页。处理：外壳落到没有序号的条目时把它**标记为起点**（`idx: 0`）——在它上面回退不可用（保守），之后 push 的条目从 0 开始正常计数，守卫随之生效。

## 3. Esc 的优先级（从上往下，谁先接住算谁的）

1. **模态层**（对话框、确认框、菜单、下拉、提示）：Radix 在捕获阶段关闭最上面一层并 `preventDefault` → 回退不动。模态层开着时顶栏按钮也点不到（body 的 pointer-events 为 none），所以"先关弹窗、再退页面"是自然顺序。
2. **行内编辑 / 输入框**：焦点在可编辑元素上时 Esc 归该控件（撤销草稿、清空搜索），回退不动。
3. **非模态抽屉**：任务抽屉焦点在内时关自己并 `preventDefault`；焦点在外时它也 `preventDefault`（现有行为，有测试）——此时回退也不动，用户再按一次（焦点在页面上、抽屉仍开着）同样不动。这是现状的保守延续：任务抽屉"吃掉"页面上的 Esc 是既定行为，暂不改。
4. **资产页**：抽屉开着或有选择时 Esc 归资产页（关抽屉 / 清选择）；两者都没有时，Esc 交给回退。（原来资产页无条件接住 Esc，改为按需启用。）
5. **都没人接**：回退一页。

实现上，回退的 Esc 监听器挂在 window、**延后到事件派发结束后再判断**（`setTimeout(0)`）：只有当没有任何处理者 `preventDefault`、没有模态层、焦点不在可编辑元素、且回得去时才 `navigate(-1)`。这样不依赖监听器注册顺序，`stopPropagation` 的行内编辑根本到不了 window，`preventDefault` 的层会被看到。

## 4. 离开守卫（防止回退悄悄丢掉没保存的东西）

`useLeaveGuard(dirty, 文案)`：基于 react-router 的 `useBlocker`（数据路由支持拦截 push / replace / **popstate**），`dirty` 时任何离开当前地址的导航（按钮、Esc、Alt+Left、鼠标侧键、顶栏点别处、Ctrl+数字）先弹确认："有没保存的 X，离开将丢弃？" 确定→继续；取消→留在原地（react-router 会把被拦下的 popstate 的历史序号恢复）。本版接入两处：

- 动作设计台的关节映射改了没保存（`mappingDirty`）；
- 密钥输入框里有内容还没点保存。

模态对话框里的草稿（图片编辑器、概念图）不需要守卫：模态开着时回退本来就不动。

## 5. 入口

- **顶栏左上角的返回按钮**（Logo 之前，`app-no-drag`）：回得去时可点，提示"返回上一页（Esc）"；回不去时禁用。
- **Esc**（第 3 节的优先级）。
- **Alt+←**（通用习惯，便宜）。
- **鼠标侧键**：主进程 `app-command` 的 `browser-backward` → 发事件 `shell:command { command: 'back' }` → 渲染层走同一个 `goBack()`，守卫同样生效（不直接 `webContents.goBack()`，否则绕开守卫和"回得去"判断）。

## 6. 不做的（这一版）

- 不做"操作级撤销"（撤销一次保存、撤销一次生成）：已提交即已提交。
- 不把模块 / 资产 / 版本切换变成 push：那会让回退在工作台内部来回，和"回到上个页面"相悖；以后若需要"工作台内回退"，另起一个明确的入口。
- 不改任务抽屉"吃掉页面 Esc"的既定行为。

## 7. 测试

- 单元（`tests/renderer/shell/back.test.ts`）：`canGoBack(state)`；`escapeShouldGoBack(event, env)` 对 defaultPrevented / 可编辑焦点 / 模态层 / 组合键 / 重复键的判定；`useLeaveGuard` 的纯判定部分。
- 端到端（`tests/e2e/back.spec.ts`，真实应用）：首页按钮禁用、Esc 无动作 → 工作台 → 拆件模块 → Esc 回到首页 → 按钮可用并能点回工作台（模块仍是拆件）→ Alt+← → 焦点在输入框时 Esc 不回退 → 打开一个对话框时 Esc 只关对话框（现有断言）→ 动作映射改了未保存时回退弹确认、取消留下、确定离开。
- 现有断言不变：任务抽屉的 Esc 行为（harness scenes-queue、trusted.cjs）。
