一键生成 3D 模型，直接进游戏引擎

文字或图片进，游戏可用的模型出——本地完成减面、LOD、碰撞体、轴心与尺寸，再直接送进你的 Unity 工程。生成由云端服务完成，用你自己的 API 密钥；本机不需要任何大模型权重。

云端生成之外的一切，都在本地做好

生成只是一步。模匠把这一步前后的工作做成一条流水线，每一步都能看、能改、能验收。

1

准备输入

图片自动抠图、构图、尺寸适配；拆分三视图 / 四视图设定图（任意网格、标签、特写框、地面线，自动判断视图方向归位）；一张正面图让概念图服务画出姿势一致的四视图；提示词优化（离线模板或你自己的大模型）；批量一行一个描述。

2

预设与预检

14 种资产类型 × 8 种目标平台 × 5 种风格，自动换算面数预算、贴图尺寸、LOD、碰撞体、轴心与真实尺寸；「展示 / 影视级」一档直接要最高几何精度和 4K 贴图；花积分之前逐项预检图片、提示词、参数、费用与余额，相对视图镜像了会提醒并一键修复。

3

云端生成

Tripo（中国区 / 国际区自动识别）、Meshy、腾讯混元生 3D，用你自己的密钥；内置离线演示服务，无需密钥即可走通整个流程。计费请求绝不自动重发。

4

本地后处理（免费）

减面到预算、LOD 链、碰撞体、轴心与尺寸校正、Unity 贴图打包；资产页可多选批量处理，一次把一批道具从 PC 预算改成移动端预算。

5

三道关卡验收

生成后、后处理后、导入 Unity 后各一道，给出 A–D 等级，每一项都说明问题和处理办法；Unity 那一关由插件回传的真实导入结果判定。

6

直达 Unity

一键写入工程的 Assets/Modelwright/；装了插件会自动建材质、带 LODGroup 与碰撞体的预制体并放进场景。桌面端和插件只走本机回环地址。

第一次使用

四步走通流程

  • 打开应用进入引导：选择生成服务。还没有密钥就选 演示（离线）——返回内置示例模型（带「示例」标记），用来走通预设、预检、后处理、验收、送进 Unity。
  • （可选）连接 Unity：应用会列出 Unity Hub / 团结 Hub 里的工程，也可以粘贴工程路径；点「安装插件」。
  • 在首页把一张图片拖进「拖入图片，一键生成并送进 Unity」，或者输入一句话描述。
  • 结果出现在首页和「资产」页；在「工作台」里查看网格、贴图、骨骼，做后处理、导出或发送到 Unity。

服务获取密钥

密钥只写入、不回显，由 Windows 加密保存在本机；界面、日志和任务记录里都不会出现密钥原文。网络默认跟随系统代理。

连接 Unity

支持 Unity 2022.3 LTS、团结引擎 1.x、Unity 6；Built-in / URP / HDRP。发送之后得到什么，取决于工程当时的状态：

工程状态结果
已装插件，编辑器开着（已连接）立即导入：按渲染管线生成材质，做好带 LOD 和碰撞体的预制体，放进场景，并把导入结果回传，验收清单的「Unity 内」一关据此判定
已装插件，编辑器没开文件先写进工程，下次打开或刷新时由插件完整导入（不放进场景，没有回执）
没装插件只写入文件到 Assets/Modelwright/，由 Unity 按默认方式导入，没有预制体

GLB 需要 glTF 导入器（glTFast）：工程里没有时，应用会让你选择「安装 glTFast（推荐）／云端转成 FBX／本地导出 OBJ」。带骨骼的模型在装了 glTFast 的工程里可以直接按 GLB 发送（Generic 骨架，不花积分）。

尚未验证

  • Meshy、混元的其余接口：贴图、重拓扑、多视图、文生 3D，以及混元的极速版、3.0 低模和国际站，仍只用模拟服务测试过。第一次请用少量积分试一次。
  • 混元动作版本在 Unity 里的蒙皮：0.1.7 查明是文件本身的绑定矩阵与层级对不上（three.js、Unity、混元自己的转换都撕裂），不是导入设置能修的；插件测出撕裂就报警告、验收清单按问题处理，请改用 Tripo / Meshy 的动作版本或重新绑骨。Meshy 带动作版本的 Play 模式同样还没有目视验收。
  • Unity 2022.3 与团结引擎：插件通过了离线编译检查，尚未在这两种真实编辑器里验收。
  • 安装程序的卸载流程没有实际运行过；安装版已在 Windows 11 上实际安装并运行。
  • 神经元绑定与试机场的边界：部件只从身体上长一层（手指、头上的耳朵并进所在部件）；紧贴身体的手臂、裙子里的腿几何上分不出来（面板按资产类型提示）；动作是程序化摆动不是步态，脚不贴地；细于一格体素的部件会被忽略（可选「精细 96」）；既没有腿也没有粗头的模型朝向按 +Z 假定。内置试机场没有物理引擎（木箱是方块碰撞，没有坡和台阶）；真实的非人形生成模型还没有拿到手测；Mixamo 的真实下载文件没有测（用的是 Meshy 的动作文件，机制相同）。
  • 动作设计台的边界：模板是程序化摆动，不是动作捕捉（脚不贴地、没有 IK），想要更真的动作仍走服务商动作库或外部 FBX；FBX 版本的设计动作只在应用内可用，要进 Unity 请以 GLB 输出绑骨再烘焙；映射依赖"身体大致直立、左右对称"，躺着的、单腿的、多头的骨架需要手动修正。
  • 极限测试与分部件建模的边界：极限测试只跑了一个角色、每轮一次，定的是基线不是规则；被遮挡区域不存在和"画上去的线变成浮雕"（睫毛成鳍、瞳孔成凸环、刘海在额头刻沟）这两件事这一版只是查清了，分部件建模只有设计草案，「部件补全」接口还没接入；8K 贴图与 200 万面的结果文件很大（59 MB / 104 MB），Tripo CDN 慢时一单要 20 分钟。
  • 拆件建模的边界：只跑了一个角色（大肥鱼）：阈值是初值；组装的固定规则（§7c）给的是起点，头发在后脑仍有空隙、尾巴根藏在裙后，最后要在手动组装面板里摆；穿插检查、组装后减面、对组装版绑骨、部件补全（Tripo mesh/complete）、C3 / C6 检查、模具的导出和仓库都还没有。"只画一对鳍"这类小附件的部件图图像模型画不好（五次都带头），已并入头发。中国区的图像任务跑 5 分钟会被服务端判失败，部件图请走国际区。
  • 裙摆保形与面部平滑的边界：裙摆仍没有布料碰撞（0.1.7 起前片随抬腿掀起，走路不再穿出，奔跑的极限帧膝盖仍可能擦到），头发不处理；面部平滑填平处的边缘还有些毛糙，肤色范围内的腮红、胡须会被当成皮肤，深肤色角色暂不识别。

已知限制：仅 Windows；只完整支持 Unity；本地后处理不处理带骨骼的模型和只有 FBX 的版本；拼音转写的多音字与超长描述有取舍。完整说明见 README。
