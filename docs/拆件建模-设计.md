# 拆件建模（分部件流水线）设计 — 草案

2026-10-25 起草。配合 0.1.11 的极限测试，尚未实现；"路线 A 实测"一节在对照跑完后补。

## 0. 为什么要拆件

- 2026-10-25 的极限测试把 Tripo 开到最高档（H3.1 超清几何 200 万面、8K 贴图、原生 2048 上传），大肥鱼 v5 的外表面细节确实上去了，但**被遮挡的区域不存在**：刘海下面没有眼睛，头发下面没有额头，掀开头发直接是壳的内腔。
- 数据：v1（193,320 面）和 v5（1,887,300 面）都是**一个封闭壳**，开放边 0、连通壳 1（v5 有 4 条非流形边）。这不是破洞，是单图 / 多视图生成的工作方式：只重建照片能看见的最外层。参数开满只会让这层壳更细。
- 人工建模的流程是一个个部件建好再组合：身体完整，衣服头发套在外面，被挡住的地方由人决定。越接近这个流程，问题越有地方修。
- 结论：把"拆件 → 制图 → 审核 → 分件生成 → 组装 → 绑骨"做成 app 内有指标、有闸门、能积累经验的流水线。不预测结果，而是在最便宜的环节测量，花大钱之前让用户看一眼，每次结果记下来。

## 0.1 第二个隐形问题：画上去的线变成了浮雕

白模模式下看 v1 和 v7 的脸（2026-10-25 对比视图）：睫毛是一圈竖起的鳍、瞳孔是同心的凸环、刘海的边缘在额头上刻出沟、嘴是一道槽。这些在原画里是**画出来的**线和明暗，生成模型把它们当成了**几何**。贴图盖上去之后看不出来（"最表面那层完成得不错"），所以是隐形的；它在四个下游环节冒出来：

- 光照一变（Unity 实时光、法线贴图），浮雕投出阴影，脸上出现脏痕。
- 绑骨动画：眼睛是刻死的凸起，不能眨眼、不能换眼神；嘴是槽，张不开；刘海和额头长在一起。
- 重新贴图：`texture_model` 往浮雕上画，瞳孔、睫毛处会出现重影。
- 减面：高频浮雕先碎，脸最先变脏。

v1（标准几何、1024 上传）和 v7（超清几何、原生 2048）都有，超清只是把浮雕刻得更清楚。这不是参数问题，是"用一张图既定形又定色"的工作方式问题。

**路线 B 的对策：每个部件两张图。** `几何用图`：平涂、无线条、无明暗、闭眼或无瞳孔的素面，只负责形体；`贴图用图`：原画细节，只在贴图步骤作为 `texture_prompt` 传入。这正是人工流程里"先雕光滑的形，再画"的分工。配套一项几何检查 **G5 面部浮雕指数**：面部区域法线的高频方差、小尺度凹凸特征计数，超阈值就换几何用图重生成，而不是等贴图盖住。

**实测（2026-10-25，头部两张图实验，各 15 积分图 + 40 积分生成）**：同一张整身图，分别画"几何用图"（平涂、闭眼）和"贴图用图"（原画眼睛），各生成一个约 100 万面的头。眼带（高度 55–80%、前半、中央 70%）的浮雕指数 F25：几何头 **0.058**，贴图头 **4.67**，差 80 倍；白模里贴图头的眼睛是刻出来的浮雕，几何头是光滑眼皮。假设成立。代价是几何用图必须绝对干净：侧视图里一团淡淡的头发残影被生成成了头顶后侧的纤维状凸起和一道面具缝，闭眼线、眉毛线也各成一道沟。因此几何用图的提示词改为"空白人台头"（无眉、无眼线、无任何线条、无光晕残影），并由 C5 把残影判为失败。**第二版（22:28）验证**：空白人台图生成的头 963,602 面、封闭、整头 R25 从 6.17 降到 **0.81**（前半 0.40），眼带 F25 0.059，宽度回到 0.79（残影造成的 0.96 没了），白模里是一颗干净的人台头：光滑头皮、眼窝只有鼓起、无任何沟缝。

## 1. 两条路线

| | 路线 A：让 Tripo 自己拆 | 路线 B：我们拆件制图再分件生成 |
|---|---|---|
| 输入 | 现有整身四视图 | 原图 → 每个部件单独一张四视图 |
| 接口 | `generate_parts`（+20）→ 追加贴图；可再 `mesh/segment`（40）+ `mesh/complete`（50 / 快速封口 30） | 每件 `multiview_to_model`（上限档 70）；组装在本地 |
| 控制权 | 怎么拆、补什么全是模型猜 | 每个被遮挡区域由我们的图决定 |
| 积分 | 约 90 | 约 300–650（见 §9） |
| 用途 | 基线与对照；便宜的"自动拆件"档 | 主线 |

路线 A 的结果决定路线 B 的三件事：部件清单的默认模板和 Tripo 的 `part_names` 命名；拆出来的件是封闭壳还是切口面（决定「部件补全」是必经步骤还是按需触发）；追加贴图后每件的贴图质量（决定分件贴图是否可用）。

## 2. 三道闸门：钱越贵的环节闸门越靠前

```
草稿 ──► 闸门一 遮挡分析（0 积分）──► 判定卡：整体 / 分件，两条路线的积分
            │ 用户选分件
            ▼
         分件制图（图像积分，每件 5–20）＋ 自动检查 C1–C6，不达标自动重画 ≤2 次
            │
         闸门二 部件图审核页：通过 / 按备注重画 / 合并 / 删除；全部通过可一键放行
            │ 放行前一分 3D 积分不花
            ▼
         分件生成（每件 30–70）＋ 每件几何检查 G1–G4
            │
         粗组装（本地）＋ 穿插检查 P1–P2
            │
         闸门三 组装审核：三维里看、微调、退回某一件
            │
         整体绑骨 ──► 完成，写入经验库
```

状态机落在资产版本上：`draft → occlusion → sheets_running → sheets_review → parts_running → assembly_review → rigging → done`，任一步可退回。

## 3. 部件模板

规则只有一条：**凡是会遮挡别的部件的东西单独成件；贴身不遮挡的并入；要单独动或单独换的单独成件。**

| 资产类型 | 部件（英文 id，固定） | 说明 |
|---|---|---|
| 人形角色 | `head` 光头含完整五官 · `hair` 含刘海后发 · `body` 内层躯干四肢含贴身衣物 · `outer` 外层服装，可多件（裙、围裙、外套、披风） · `shoes` · `acc_*` 配件（帽、武器、翅膀、尾巴，各一件） | 袜子手套并入 body；发饰默认并入 hair，用户可拆 |
| 生物 / 四足 | `body` · `head`（可选） · `mane` / `tail` / `wings`（有则单独） | 毛发遮挡身体时 mane 单独 |
| 道具 / 载具 / 建筑 | 按可动件拆：`door_*` `wheel_*` `turret` … | 没有可动件就不拆 |

清单由模板给默认值，视觉模型看原图确认哪些存在，用户在判定卡上勾选增删。Tripo `part_names` 到这些 id 的映射等路线 A 实测后定。

## 4. 闸门一：遮挡分析

分两级，一级立刻、零积分；二级可选、只花图像积分。

**一级（规则）**
- 脸被头发挡住超过一成 → 分件（头一歪刘海下面就露出来，正是这次的问题）。
- 有裙子、披风、宽松外套 → 分件（走路时腿和身体必然露出来）。
- 需要单独动或单独换的东西（武器、翅膀、尾巴、帽子） → 分件。
- 道具、建筑等静物，或以上都没有 → 整体生成。
- 一级的"有没有刘海 / 裙子"先由类型模板加用户勾选回答；本地像素启发式（肤色区域与头部框）只做提示，标为弱证据。

**二级（测量）**
- 先只画最关键的两件：`head` 和 `hair`（约 10–40 积分）。
- 脸部被遮挡比例 = 光头图的脸部掩膜 − 整身图正面可见的脸部掩膜，按整身图位置框归一化。
- 超过阈值（初值 10%）即确认分件，这两张图直接进入闸门二，不浪费。

**输出：判定卡** `{ route: 'whole' | 'parts', reasons: [...], hiddenRatio?: number, costs: { whole, parts } }`，默认跟判定走，用户可改。

## 5. 分件制图与自动检查

每件一张 4:1 的四视图设定图，复用现有「四视图设定图」模板和「拆分设定图 2.0」；整身四视图作为参考图一并传入（Seedream 5 / Banana 2 / Banana Pro / chat_image 2.5 都支持多参考图）。

**指令模板**（中英各一份，部件专属片段拼接）：

> 只画这个角色的【部件】，其他部分一律不画。与参考图同一相机、同一 A 姿势、同一比例和位置；正、左、背、右四个视图排成一行；纯白背景、无阴影；物体必须完整，参考图里被挡住的面也要画出来。

部件专属片段：`head`「光头，完整的脸，双眼睁开，不画头发」；`hair`「只画头发，像一顶空心的帽子，不画脸和皮肤」；`body`「穿贴身内层衣物的身体，不画外层服装和鞋」；`outer`「只画这件衣服，保持穿着时的形状，里面不画身体」；`shoes`「只画这双鞋」。

每件固定一个随机种子；重画时把失败的检查项写成一句话追加到指令末尾。

**自动检查**（全部本地，用现有抠图、`splitSheetMask`、`classifyViews`、同侧镜像检测）：

| 编号 | 检查 | 初始阈值 | 失败后 |
|---|---|---|---|
| C1 | 拆出四个视图，**顺序按提示词约定取**（一行从左到右 = 正、左、背、右），外观分类只作一致性警告 | expected = 4 且 layout = row；外观分类与约定不符时 warn | 重画 |
| C2 | 四视图高度一致 | 高度变异系数 < 3% | 重画 |
| C3 | 轮廓对齐：部件掩膜落在整身掩膜（膨胀 2%）内；部件高度 / 整身高度与模板估计比例一致 | 溢出 < 5%；比例偏差 < 8% | 重画，指令加"按参考图比例" |
| C4 | 部件专属规则：`head` 几何用图脸上无线条（细笔画占比，正面 ≤ 1.5%、侧面 ≤ 0.8%）；`hair` / `outer` / `shoes` / 配件 图上无肤色像素（> 2% 警告、> 5% 失败）；`body` 两个侧视图宽度 < 正面的 80% | 见左 | 重画，指令加对应片段 |
| C5 | 干净：四个视图之外无杂块（< 0.5%）；**两个侧视图镜像后轮廓重合 ≥ 80%**（擦掉一条、带残影都会破坏镜像；左右本就不对称的部件如尾巴跳过）；主体周围背景带色调 > 3% 只警告 | 见左 | 重画 |
| C6 | 风格一致：与整身图的色板距离 | 初值待校准，先只警告 | 警告 |

每项输出 通过 / 警告 / 失败 和一句可读理由；失败自动重画最多 2 次，然后交给用户。

**C1 为什么不能沿用整身图的视图归位（2026-10-25 实测）**：光头几何用图的四个视图，`splitSheetMask` 切得很准（4 块、row、confident），但 `classifyViews` 把四块全判成 front——它靠"头部区域的肤色占比"分前后、靠轮廓对称度分侧面，而光头从哪面看都是肤色、都挺对称（对称度 0.88–1.0，肤色 0.96–0.97）。`assignViews` 于是只留一个 front，面板里就只剩 3 个视图。部件图的顺序是我们在提示词里规定的，直接按位置取即可。

**成对的部件与两条新的 C4（2026-10-26 实测）**：鞋和鳍的部件图每个视图是两块（左右各一只），`splitSheetMask` 报 6 个图形，C1 直接失败。部件图的拆分现在不套整身图的两条"特写"规则——内容沿框边直线截断的块是特写、比中位长宽比扁得多的块是特写：头箍的平顶、袖口的平切、鳍根的平切都会中招，头发和外层服装的正、背视图被整块丢掉（卡片上的"拆出 2 个视图"就是这么来的）。一行里多于四块时按最宽的三条空隙分成四个视图，每块是视图的一部分；一块比同视图的其它块矮六成以上就不是另一只鞋而是杂块，不分组，照旧按块数失败。切片也按检查定下的四个视图裁，裁切器与检查永远一致。同一天补的两条 C4 来自两张 C1、C2、C5 全过的图：外层服装的几何用图长出一颗光头（20% 肤色像素），身体的几何用图四个视图全是正背面（侧视图宽度是正面的 99%）。

**侧视图的左右也不能全信提示词**：提示词写的是"LEFT SIDE view (the part's own left towards the camera)"，Banana 2 两次都把第 2 个视图画成鼻尖朝左。所以位置只定"正 / 侧 A / 背 / 侧 B"，两个侧面哪个是左哪个是右要从图形本身判，判不出时按提示词约定。

> **约定更正（2026-10-26 深夜）**：上一段原写"鼻尖朝左 = 角色右侧朝镜头 = 右视图"，是错的。相机在角色左侧看过去，角色的正面（鼻尖）指向画面**左**边——站在面朝北的人西边看他，他的鼻子朝你的左手边。所以**左视图 = 正面朝画面左**，与提示词的写法一致，也与 Tripo 的约定一致（头部件送去的左视图鼻尖朝左，生成正常；身体部件送去的左视图正面朝右，生成出两面都有蝴蝶结、每只手前后各一根大拇指的六指怪）。

**侧视图朝向的判定规则（2026-10-26 深夜补）**：`sideFacings`（`src/renderer/src/workers/image/partsChecks.ts`）先用部件自己的规则——头用下巴 / 鼻子（`headFacing`），身体和鞋用脚尖（`feetFacing`：脚那几行比小腿中线向前伸得远的一侧是前，实测侧视图 0.10–0.14 个图宽，正背面 0.02 以内）；读不出再用颜色线索（`colourFacing`：只有正视图才有、背视图没有的颜色——蝴蝶结、脸——在侧视图里落在哪一侧，哪一侧就是前）。两条都判不出时，C1 按提示词顺序归位但**只给警告**（"请核对第 2 个视图是否正面朝左"），这张图不再自动放行。判定与顺序相反时 C1 写明"第 2 个视图正面朝右，已作为右视图"。已放行的图用「重新拆分检查」按当前规则重判，不用重画。

**试过但不成立的几何侧检查**：在生成件上量前后深度图的镜像程度（G8）。身体怪胎 81% 的格子前后不同，正常的头也是 81%——身体本来前后就处处不同，多出来的一只蝴蝶结和两根大拇指太小。当晚撤掉。

**贴图用图的新失败模式**：第 2 个视图的眼鼻区域被模型"擦"出一道横向白斑。C5（干净）要加一条：主体内部出现大片接近背景色的连通区域 → 失败重画。

**审核页**：整身图在左，部件卡片在右；每张卡片列检查结果，不通过的排最前；按钮：通过、按备注重画、合并到某件、删除；全部通过时显示"一键放行"，旁边写明放行后的 3D 积分。

## 6. 分件生成与几何检查

- 每件走 `multiview_to_3d`，按预设档位（极限：H3.1 超清 + 8K；展示默认：4K；游戏：标准）。贴图在生成时直接出，**不用** `generate_parts`。
- 面数预算按部件面积占比分配，总和不超过档位上限：head 25%、hair 25%、body 20%、outer 20%、shoes 5%、配件 5%。
- 几何检查：G1 开放边 = 0；G2 连通壳 = 1（hair 允许 ≤ 3）；G3 面数在预算内；G4 包围盒长宽比与设定图相差 < 15%；G5 面部浮雕指数（见下）。G1 失败的件走「部件补全」（50）或本地快速封口。
- **G5 定稿**：只量**眼带**（部件高度 55–80%、前半、中央 70% 宽）：F25 = 眼带内二面角超过 25° 的边的总长 ÷ √眼带面积。同密度下初始公差：≤ 0.5 通过，0.5–2 警告，> 2 失败（实测：几何头 0.058，贴图头 4.67）。
- **浮雕指数的来历与一个坑**：整头的 R = 二面角超过 25° 的边的总长 ÷ √表面积（`src/main/workers/mesh/parts.ts`）。它随网格密度变化：同样的形状，面越少每条边的二面角越大。实测大肥鱼整身 v1（19.3 万面）R25 = 81，而 v7 的头发脸躯干一块（86.7 万面）R25 = 17，并不是 v7 更光滑。所以 G5 只在**同一密度**下比较：流水线里先把部件简化到统一密度（每单位面积固定面数）再量；实验里两个头用同一面数预算生成。前半/后半（沿前向轴）分开报告，脸在前半。
- 入库：每件是资产下的子版本，`kind: 'part'`，带 `partId` 和所属「拆件方案」。

## 7. 组装

- **底座**：整身模型。已有就复用；没有就用标准档生成一个白模（20 积分），只做对齐参考。
- **粗放**：每件在正面图和侧面图里的位置框 → 三维包围盒（x 取正面，z 取侧面，y 共用），按角色身高缩放。Tripo 输出是归一化尺寸，每件按设定图算出的尺寸重新缩放。
- **精配**（第二阶段）：对底座上也存在的部件（头发外层、身体），点到面 ICP 对齐。
- **穿插检查**：P1 两两部件之间，采样顶点做奇偶射线测试，统计落在对方内部的比例；P2 部件间最小间距。允许的嵌套：head 在 hair 内、body 在 outer 内、脚在 shoes 内；其余超过 2% 警告，超过 10% 退回。
- 输出一个多网格 GLB，节点按 `partId` 命名，材质按件；引擎需要时再合并。

### 7b. 第一次真实组装的教训（2026-10-26）

六件（头、头发、身体、外层服装、鞋、尾巴）各自拟合到整身底座：头、裙、鞋位置正确，但头发缩进了头骨（缩放 0.566，光头从发帽里露出来，只剩呆毛、头箍和侧发露在外面），尾巴缩成 0.19 藏在裙后。原因是点对点 ICP 分不清"贴在表面外"和"缩进表面内"：发帽的内外两层都能贴到底座的头部表面上，而且底座是一个壳，头骨和头发表面在同一片点云里。

改法——**按嵌套顺序逐件拟合，后面的件只对齐前面的件没解释掉的底座点**：

1. 顺序：先拟合不套别人的件（头、身体），再拟合 `nests` 指向它们的件（头发→头，外层服装 / 鞋→身体，尾巴→身体 + 外层）。
2. 每拟合完一件，底座上离它 1.5% 身高以内的点标记为"已解释"。
3. 套在别人身上的件只对"未解释"的底座点做 ICP（少于 2,000 点时退回整个底座）：头发看到的是底座的头发表面而不是下面的头骨，尾巴看到的是裙子之外剩下的那截。
4. 头、身体仍对整个底座拟合；合成测试显示底座里包着它的壳（发壳）会在名义起点偏 4% 时把头拉大 10%——名义带准时影响很小，之后可以给核心件用更紧的裁剪比例。

还没做：穿插检查、组装后减面、对组装版绑骨。

### 7c. 组装的固定方法（2026-10-26 定稿，第四次组装起生效）

用户在看过三次组装后的判断：部件按图纸做出来质量稳定，组装却在"摸"；组装必须像精密图纸一样提前定好规则。定稿如下——**每件按模板角色选一种放置方法，不再一把 ICP 套所有件**：

| 方法 | 用于 | 规则 | 依据 |
|---|---|---|---|
| `fit` 拟合 | 头、身体、外层服装、鞋 | 裁剪 ICP 贴到整身底座（套在别人身上的件只对齐前面各件没解释掉的点） | 这几件在底座上有独一无二的大面（脸、躯干、裙、鞋），三次真实组装都对 |
| `wrap` 包裹 | 头发（包住头） | 不拟合，按头放置。先量发帽的空腔（上半段每片切片里离中心最近的内壁，取最宽的一片）：空腔 ≥ 外轮廓 60% 的是**薄壳**，按空腔套头（内后壁贴头骨后缘、内顶贴头顶、空腔中心左右对齐，留 3%）；否则是**厚帽**（Tripo 的常态，大肥鱼的空腔只有外轮廓的三分之一），按外轮廓放：缩放 ≥ 包住头的水平范围 +4%、顶部对齐全身最高点、左右居中、**外后缘在头骨后缘之后 6% 头深**（发帽一定盖住后脑，刘海伸到哪算哪；按包围盒居中会被鼻子把发帽推到前面）。头骨落在厚帽的实心里，看不见 | 底座是一个壳，头发下面没有头骨，表面给不出发帽该多大、多高；头能给。第七次按固定 12% 余量放，刘海盖到了脸上：余量不能猜，要么量空腔、要么按外轮廓小余量 |
| `region` 区域 | 配件（尾巴、翅膀、帽子、武器） | 先定**方向**：配件顶部 5% 的切片是接口（平切处），离接口最远的点是自由端，绕竖轴转到自由端朝离开身体的方向（背侧配件朝 −x、前侧朝 +x）；再取底座上前面各件都没解释掉、且在名义高度带 ±10% 内、位于该侧半边的点，按 3% 身高的体素做 26 连通聚类取最大一簇：缩放按簇的水平范围（限制在名义的 1/1.5 ～ 1.5 倍）、底对齐簇的底、水平居中 | 配件在底座上只露出一部分，ICP 会把它缩到贴住裙子；配件图的"正视图"是它自己的视角，生成出来的朝向与角色无关（尾巴横在身侧） |

另加一条形体规则：**外层服装的裙摆开口**——Tripo 把裙子底下封成实心盖子，组装时把最底 4% 高度内朝下的面去掉，露出腿（`openBottom`）。

每条规则都有合成测试（`assemble.test.ts`：嵌套顺序、解释掉的面、包裹放置、区域放置、区域候选、裙摆开口）。

第四次真实组装（按头放置后头发终于戴对了）暴露了区域法的一个坑：按规则放置的头发与底座的后发对不到 1.5% 身高以内，底座的后发整片留在"未解释"里，和尾巴连成一簇，尾巴被放大到 0.825。所以区域只在配件的名义高度带（±10% 身高）里取，背侧配件只取底座中线以后的点，放置后的缩放限制在名义缩放的 1/1.5 ～ 1.5 倍之间。规则表写在 `shared/data/parts.ts`（`assemblyMethod` / `partWraps` / `partOpening`），面板的拟合列表记方法与对齐点数。

**手动组装（2026-10-26 当天加上）**：用户看完八次自动组装的结论——规则只能给起点，最后要由人来摆。组装体的工作台里，「拆件」模块变成手动组装面板：每个部件节点一行，改前后 / 上下 / 左右 / 缩放 / 旋转，视口实时跟着动，「按当前摆放重新组装」把摆放原样写成新版本（请求里的 `manual` 放置，规则不跑）。自动规则产出的 `·组装` 版本就是手动的起点。

**0.1.13 主项——组装工作台**（用户 2026-10-26 的方向：手动面板模仿 Unity 的布局做成工作台模式，拼完接打包一条龙，用户只管发挥想象力拼）：
- 布局仿 Unity：左侧层级（每件一行，可显隐 / 选中）、右侧检视器（选中件的位置 / 缩放 / 旋转，数值与拖拽同步）、中间视口。
- 视口里的拖拽手柄：三轴移动、缩放、绕竖轴旋转（three.js `TransformControls`），吸附到地面与对称轴；选中高亮、相机聚焦到件。
- 自动规则（§7c）的结果是起点；位置图（下一段）让起点更准；每次「按当前摆放重新组装」产出新版本，摆放记在方案日志里可回放。
- 拼完直接进现有的一条龙：后处理（减面 / 补洞 / 平滑）→ 绑骨 → 动作 → 发送 Unity，与整身模型同一条路，组装体不再是「另一种资产」。

**再往前一步（0.1.13 候选）——位置图**：现在的"图纸"是整身底座本身（规则从它上面量）。更干净的做法是每件多画一张**位置图**：角色其余部分浅灰剪影、该部件原色，正、侧两个视图；从图上直接量出部件在全身里的高度带、宽度比和前后位置，组装只做放置（缩放 = 比例 × 身高，位置 = 带的中心）再做小幅拟合。部件图本身不能当图纸，因为每张图都按自己的尺寸铺满画布，件与件之间没有公共比例尺。

### 7d. 部件路线第一步：确认的摆放、三轴旋转、换件与头发配合检查（2026-11-01）

依据：一份内部任务书（未公开） §6 第一步（零积分），以及用户同日的定位：手拼不追求让 AI 自动拼，路线只需要把前后接好、中间交给用户。实验记录在私有仓库。

起因（B 的尝试，实验记录在私有仓库）：自动组装出的 B 头顶、后脑露皮，胸前横着一片；我按数值搜摆放、在组装台手摆都没有拼好，尾巴的问题也是用户指出的。手拼本身还有三个工具缺口：只能绕竖轴转（尾巴抬不起、压不下），摆放只存在组装出的 GLB 里（换一件就没法按原摆放复原），没有办法判断头发和头配不配。

**做了什么**

1. **三轴旋转（`shared/mesh/partRotation.ts`）**：转向 · 俯仰 · 侧倾 = Ry · Rz · Rx（three.js 的 'YZX'），在整身坐标里：转向绕竖轴，俯仰让前端抬起（+）或压低（−），侧倾让顶部往 +z 倒。渲染进程和 worker 用同一份换算；视口读回用不取整的精确值（不取整，写回不漂移）。贯通：旋转手柄三个环都开放、多选跟随按完整旋转绕主件、Q / E 转向保留俯仰和侧倾、检视器加「俯仰 / 侧倾」、`ManualPlacement.pitch / roll`（可选）、worker 写进节点四元数、重开读回。旧摆放只有 yaw，按原效果读出（俯仰、侧倾为 0；四元数与以前逐位相同）。
2. **确认的摆放（`PartsPlan.layout`，`parts/layout.ts`）**：「按当前摆放重新组装」就是用户的确认，记下每件的模型版本、缩放、位置、三个角度和它在整身坐标里占的盒子。之后部件页的「组装」按记录摆：同一个模型 = 按确认的摆放（`kept`）；换了模型 = 放进原来的盒子（居中，缩放取三个轴比例的中位数，worker `placeInSlot`，方法记 `slot`），标「请检查」（`replaced`）；依附在它上面的件（`spec.nests`，头换了 → 头发）照原样放、也标「请检查」（`dependent`）；还没确认过的件按规则放（`new`）。组装台有「按记录还原」，并显示当前摆放与记录是否一致。没有记录时组装台明说「这是自动摆放给的起点」。
3. **用资产库里的模型当某一件（`parts/replace.ts`）**：部件页每件可选一个静态 GLB（带骨骼 / 动画的不行：组装会合并网格）。用户能把别处做的、从整体拆出来的、或试配合用的壳放进方案；换件按上一条处理。
4. **头发与头的配合检查（`shared/parts/coverCheck.ts` + `viewer/coverCheck.ts`）**：头部件的「脸部区域」是头的一个接口（`PartsPlan.faceRegion`：下沿 / 上沿 / 半宽，占头部件自身包围盒的比例），把头的三角形分成脸 / 头皮 / 其他。围着头从 9 个方向各渲染两遍（只画头、画上全部部件），逐像素比：正面三个方向里脸还露出多少，所有方向里头皮露出多少；合格要求脸 ≥ 90 %、头皮 ≤ 5 %，注意是 75 % / 15 %。结果带四张标色图（红 = 头皮露出，橙 = 脸被挡，绿 = 脸露出）。按可见性判断，而不是「头的点在不在头发体内」（Codex 对 B 体素统计的意见：发型不必包住每个顶点，开口处的点也看得见）。默认脸部区域只在一颗头（大肥鱼 Q 版头 04 的正面渲染：眉 ≈ 69 %、下巴 ≈ 16 %、脸颊 ±36 %）上量过，置信度低，组装台里可改，改后存进方案。
5. **小修**：部件页把手动摆放（`rms = −1` 哨兵值）显示成「残差 −1000.0 mm」→ 现在写「手动摆放」，换件的写「换过模型，放进原来确认的位置」；「组装 N 件」完成后的提示改成「自动摆放只是起点……去组装台自己摆」；组装台「下一步」说明先后处理减面、再在后处理出的版本上绑骨（后处理会把各件合成一个网格，所以要先摆好）。

**实测（真实部件，隔离的实验数据，0 积分）**：头 04 + 头 04 自己的头皮三角形外推 2 % 做成的壳（**正例，只验证装配系统，不代表 AI 头发的质量**）、B 原来那顶头发（反例）、其余四件照旧。
- 壳按自动规则摆：脸 75.8 % / 头皮 0.3 %（注意：规则把壳放偏，挡了一部分脸）；手摆到头的位置：脸 94.1 % / 头皮 0.5 %，合格。
- 尾巴俯仰 −25°、侧倾 8° → 确认 → 重开：六件的位置、缩放、角度与记录差 0（角度 3×10⁻¹⁴°）；GLB 文件里的节点变换与记录差 0。
- 拆开（头前移 20 cm、转 40°，尾巴回正，头发转 30°）→ 显示「与记录不同」→「按记录还原」→ 一致，差 0。
- 头发换回 B 那顶：头发标「换了模型」，其余五件「按确认的摆放」；重新组装后头和其余四件的变换差 0；配合检查脸 69.9 % / 头皮 66.3 %，不合格。B 的自动组装原样检查：脸 54 % / 头皮 50.4 %，不合格。
- 合成 e2e（`tests/e2e/parts-layout.spec.ts`：球形头、挖开脸的帽壳、挡脸的帽壳、方块身体）：确认 / 重开 / 还原 / 换件 / 检查合格与不合格都覆盖。

**限制**
- 只验证了「同一基体下一件可替换的部件」的装配系统，没有验证任何生成出来的头发能配合；正例是按头构造的壳。
- 换上形状差很多的件时，「放进原来的盒子」只是粗略起点（B 的长发放进壳的盒子被缩得很小），仍要用户在组装台调。
- 旋转绕部件自己的原点（Tripo 部件通常是中心），不是它接在身上的那一点（尾巴根）；连接点留到下一步。
- 配合检查只看头发与头；尾巴、衣服与身体的穿插、接缝没有检查。脸部区域的默认值只量过一颗头。
- 这一步不碰生成：没有花积分，也没有改变部件的生成方式；路线是否值得继续，按 Codex 规划 §6 的继续 / 停止条件判断。

**第二步（还没做，要先审）**：只把「头发怎样适配这颗固定的头」作为未知，候选两种，各一次：A. 对已有满意的整体模型做 Tripo 分割（40 积分），看能否得到与头分开、位置不变的头发（0.1.12 实测过切口开放、部件无名，头发和脸连在一起的风险高）；B. 用固定头的正 / 侧 / 背渲染做条件画一张只含头发的部件图（约 15 积分），再生成这件头发（约 50 积分），按已知的头变换导回后跑配合检查（约 65 积分，信息量更大：能直接回答「以头为条件的头发能不能少改就配上」）。

### 7e. 部件主线整改第一阶段：B 的正确拼法、产物身份、朝向确认与检查器口径（2026-11-02，0.1.22 候选）

依据：一份内部任务书与独立复核（未公开）。实验记录在私有仓库。

**对 §7d 和 2026-11-01 B 尝试的更正（原文保留）**：「这顶头发和头怎么摆都盖不好」不成立。我的数值搜索只遍历了缩放和平移，没有转向；B 的头发相对头 04 前后是反的，转向 180° 后长后发回到脑后、刘海回到额前（同参数只改转向的对照：`lab/01-repro-yaw0-vs-yaw180.png`）。胸前那块深色是尾巴，不是头发封住的脸口：只隐藏头发时它还在，只隐藏尾巴时它消失（`lab/02-chest-block-source.png`）。尾巴缩到 0.3、下移约 10 cm 后胸前遮挡消失。「必须先重新生成头发」的判断过早；B 现在是一个可编辑、可保存的静态组装。

**正确的拼法（以后照这个顺序）**：先认准角色真正的前方（看五官，不看视角按钮的名字）→ 固定参照件 → 逐件隐藏确认问题属于哪一件 → 先摆对大方向（前后、左右、上下，必要时比较四个水平转向）→ 按接合区域定统一缩放（头发看头冠与发内侧，长后发可以超出旧短壳的盒子）→ 位置，每改一轴看对应侧面 → 最后小角度俯仰、侧倾 → 恢复全部可见、多视图检查 → 保存、读回、重开。证明原因时固定其他条件只改一个变量。

**改了什么**

1. **产物身份（A）**：每个组装产物的部件节点写上它来自的源版本（worker 节点 extras `partVersionId`，视口行 `sourceVersionId`）。组装台按屏幕产物的真实身份核对部件计划（`parts/layout.ts` `assemblyIdentity`）：一致才允许确认；某件与方案不一致（方案里换过）时不能把旧件的摆放记成新件已确认，按钮变为「加载方案里的新件」（新件放进旧件的盒子、朝向待确认，其余各件按现在摆放，生成新产物）；旧产物没有清单时只提供「按当前摆放重新组装（不确认）」，生成带清单的新产物后再确认。记录只从屏幕产物的版本生成（`layoutFromRows`）。
2. **待导入记录（A）**：「按当前摆放重新组装」把摆放存为 `PartsPlan.pendingLayout`（绑定确切 job ID），导入成功才升为 `layout`；失败或取消时上一份确认记录和产物不动，新摆放标为失败草稿，可「取回这份摆放」；迟到的旧任务结果不覆盖新草稿，也不移动 `assembledVersionId`（`assembledAfterJob`）。
3. **还原与比较（A）**：「按记录还原」只还原与记录同版本的件，换过的件保持现状并提示；比较按等价旋转（四元数夹角），141° / 120° / 8° 与 −39° / 60° / −172° 视为同一朝向；记录里换过模型的件单独标「换过」。
4. **朝向确认（B）**：不再默认每件都朝 +X。新件、换过的件标「朝向待确认」（不沿用旧件的朝向），检视器给「转 180°」和「朝向没问题」，确认绑定到该件的源版本（`PartEntry.orientation`）；已确认的布局里同版本的件视为已确认。组装台加「看角色」一排视角（看脸 / 后脑 / 左右 / 顶部，按组装坐标里角色朝 +X）；视口自己的视角改标为世界坐标轴（「正面 · 从 +Z 看」）。外框放置（slot）保留为粗起点并写明：长发按旧短壳外框估算会偏小（三种外框规则 0.50–0.64，手调 0.75），接合区域判断留给用户。
5. **检查器口径（C）**：判定只算指定的头发（头 + 头发），其他部件不替头发加分；全部部件的结果单列为「参考」。脸部区域下沿必须低于上沿、半宽 > 0，否则不保存。脸或头皮像素少于 200 时为「无法判定」，不再默认判合格。头或头发有透明 / 裁切材质时最多「需要注意」。检查与列表里的显示 / 隐藏无关（写在界面上）。脸部区域记下设定时的头版本，换头后提示重新核对。

**实测（受控库副本 lab27，0 积分）**：复现审计的 B（六件变换差 0）；用新构建保存（旧产物 → 重组带清单 → 确认头发朝向 → 确认）；检查器只算头发：脸 100 %、头皮 8.1 %（需要注意，红色是刘海下沿与眉线之间的一条额头，后脑、头顶全覆盖；全部部件参考：脸 97.5 %）；尾根在侧后方有一截粗大的根部露出裙外，小幅调整（前移 3 cm、下移 2 cm）减小但未消除；冷启动（源构建）与打包候选冷启动都读回一致；取消导入的反例：旧记录、旧产物保留，新摆放成为失败草稿可取回；兼容发壳转 90° 的副本：沿用旧转向检查不合格（脸 80.8 %、头皮 31.2 %），按 E 一次后合格（99.5 % / 0.5 %）。后处理候选：39,997 面、6 材质、1.75 m，二次元风格预设去掉了法线贴图（设计如此）。

**限制**：尾根造型的可见残留与变形风险留到绑骨阶段观察；外框放置对差别大的替换件只是粗起点；朝向不做自动语义识别；检查器的默认脸部区域只量过一颗头、眉线以上算头皮（露额头的发型应调高上沿）；透明材质只提示不精确计算；旋转仍绕部件原点，没有连接点。

### 7f. 同源布局复用与两个状态边界（2026-11-02 晚，0.1.22 候选第二轮）

依据：一份内部任务书（未公开）（附独立复核里的三个反例，未公开）。实验记录在私有仓库。

**改了什么**

1. **完整集合（P1）**：`assemblyIdentity` 对照组装实际会用的那组件（启用 + 已生成 + 有版本），列出缺失（计划有、产物没有）、多余（产物有、计划已停用或删除）、重复、版本不一致、没有清单。只有完全一致（`complete`）才允许确认；其他情况按钮为「载入实际部件（不确认）」：同版本的件按屏幕摆放，换过的件进旧盒子，缺的件取已确认记录（没有记录就按规则），多余的件不再组装，生成新产物，看过再确认。`assembleParts` 在提交确认或重放前再核一次：记录必须恰好覆盖要组装的件，否则拒绝，不写文件。`compareWithLayout` 同时比两边集合（`unrecorded` / `absent`），全部一致才算「一致」；组装台的记录行多一种状态 `set`。
2. **按自己的任务结算（P2）**：结算集中在 `parts/useAssemblySettlement.ts`，组装台和部件页共用。pendingLayout 自己的 job 和最新一次组装的 job 分别盯；两者谁先结束都各归各位：确认的成果记在 `layout.assembledVersionId`，最新产物记在 `plan.assembledVersionId`，两者不同时部件页写明「最近一次组装还没确认」。结算是幂等的（日志记着哪个任务结算过）。任务仓库每次启动从主进程重建，重启后照样结算；任务记录已被清掉的 pending 标为失败草稿（`job:lost`）。界面上串行：确认的摆放导入中时，部件页和组装台的非确认组装不可用。
3. **读回后才转正（§五 4）**：worker 在产物里写入每个部件节点的源版本和源文件 SHA-256（`partSha256`），在场景 extras 写坐标约定 `assemblyFrame = 1`、整身底座版本和 SHA-256。主进程新增 `library:assemblyHolders`，只读 GLB 的 JSON 块。确认或重放的导入成功后先读回比对：部件集合、版本、源内容摘要、平移和缩放（1e-9）、旋转（记录有精确四元数时 1e-6°）、底座、坐标约定。全部一致才转正；否则标为失败草稿，写明哪一件哪一项（`readback:hair=transform`）。
4. **源内容摘要（§五 3）**：主进程组装时给底座和每个部件文件算 SHA-256。与入库时记录的不一致（文件在库外被改过）直接拒绝；重放要求的摘要对不上时拒绝并点名部件。记录保存每件的摘要、精确旋转（四元数）、底座摘要、坐标约定、产生它的 job；2026-11-01 的旧记录在第一次重放时补全。手动摆放可以带精确四元数，worker 原样写入。
5. **同源重放入口（§五 2、5、6）**：部件页先判断记录能否原样重放（`replayDecision`：同一组件、同一版本、底座还在、同一坐标约定）。能：「打开已确认的组装」（先读回核对，不导入，不堆同名资产；没有场景记录的旧产物只核对部件节点）和「按确认的摆放重新生成」（逐件核对源内容，导入后读回；确认时间不变，另记 `replayedAt`）。不能：写明新加 / 移出 / 换了 / 依附的件换了 / 底座不在 / 坐标约定变了；按钮写「组装 N 件（未变的件按确认的摆放，变了的要检查）」，不说成全部恢复。
6. **语义收口**：「朝向没问题」改为「朝向已检查」，界面写明它只记下看过、不保存角度；角度只随确认的摆放保存，自动化只读成功的 layout。外框放置写明「旧件的转角只作起点，确认状态不沿用」。

### 8a. 实测（2026-11-02，r30，大肥鱼六件成品）

**多网格可以绑，合成一个网格反而不行。** 全部用 Tripo 的免费预检（`animate_prerigcheck`，只回 `riggable` 和推荐骨架，不给原因）逐项对照，余额全程不变：

|---|---|

| 同上，6 万 / 10 万 / 15 万 / 25 万面 | 都不能绑 |

**绑骨结果（v3.0，原生命名，GLB，25 积分）：** 78 根骨骼（含扭转骨、手指、眼睛），A 姿势（上臂低于水平 35°–40°），六件全部蒙皮、没有零权重顶点、每点最多 4 根骨。Tripo 回的是 1 m 高，下载时按源版本还原到 1.75 m，原始文件留作 `model.provider.glb`，`scale-restore.json` 记倍数。

**动作检查（动作设计台的模板，内存里，不写库）：** 待机、挥手、跳正常；走和跑有两个问题。
1. 尾巴跟着左腿走（Tripo 的权重）。
2. 裙摆保形器把尾巴和身体里的衬裤也当成裙摆（尾巴的顶点都由大腿主导、又离腿远），一部分顶点挂到直立的 helper 上，相邻的还跟腿走，走跑时撕成碎片和白色长条。关掉保形器时不撕，但裙摆跟着前腿掀起来。

### 8b. 权重整理（2026-11-02，r31）

**先修实验。** r30 的「只给外衣参与保形」对照无效（切模板时保形器又自动挂上全模型，四对截图逐字节相同）。r31 把开关做成产品里的视口策略（`auto` / `off` / `legacy`，工具栏按钮，切换即重新加载模型），每次截图前记录实际策略、保形器判定与挂载、辅助骨、每个蒙皮网格权重的摘要，条件不符就不出图。四组对照（受控库，同一动作、同一时刻、同一机位）：

| 分支 | 权重 | 保形 | 尾巴尖位移（走 / 跑） | 画面 |
|---|---|---|---|---|
| B1 | 原始 | 关 | 0.52 / 0.82 m | 尾巴随左腿甩；右手把前裙拉成尖角 |
| B2 | 原始 | 旧版全模型 | 0.07 / 0.10 m | 尾巴和衬裤被挂到辅助骨，撕成碎片和白条 |

| B4 | 整理后 | 自动（只驱动文件自带辅助骨） | 0.07 / 0.11 m | 同 B3，裙摆保持下垂 |

**修法（显式作用域，不猜）。** `shared/mesh/skirtFix.ts` + 流水线步骤 `weight_fix`（wrapper 模式第一步，在输入文件自己的帧里）：
- 部件对应：拆件计划里每件的模型文件节点名 ↔ 绑骨文件的网格节点名（组装保留了部件节点，后处理加 `_LOD0`，服务商截短），唯一前缀匹配才算对应（`shared/mesh/weightFixProposal.ts`）。
- 锚点：一件整个刚性跟随一根指名的骨头。按角色提议尾巴 → Pelvis；不是「离哪根躯干骨最近」。
- 裙摆区域：外层服装里 y 低于顶部高度、离手臂骨段超过袖子半径的顶点。区域内手臂骨的权重改给髋部并归一化，再按旧保形器的铰链 / 四象限规则挂到 `SkirtRoot_FL/FR/BL/BR`（新加为髋部子关节，逆绑定 = 髋部）。区域外、其他网格一个顶点都不改；记录里按网格写改动数。
- 数值在世界米制里读（服务商文件由缩放根还原尺寸时，顶点数据仍是 1 m 比例：第一次实现读了原始帧，0.47 m 变成了 0.82 m，单测 `weightFix.pipeline.test.ts` 用缩放根夹具钉住）。
- 保存：普通后处理派生版本，请求存在 recipe.overrides.weightFix，结果存在 manifest.weightFix 和文件根 extras；原绑骨版本和 `model.provider.glb` 不动。

**运行时与出口一致。** 辅助骨的驱动公式只有一份（`skirtHelperRotations`）：查看器 `auto` 对带辅助骨的文件只驱动不改权重；烘焙（`motion.ts`）和导出按钮（`bakeSkirtHelperTracks`）把每段动作的辅助骨旋转写成轨道；Unity sidecar `cloth: baked`，插件对带辅助骨的模型什么都不加、也不删它的关节；多网格且无辅助骨的模型插件和查看器都不再检测（提示先做权重整理）。单网格模型行为不变。

**边界。** 尾巴刚性，没有动力学；袖子半径和顶部高度是人工可改的两个数，默认由骨架提议；新加动作要重新导出才带裙摆；普通 GLB 播放器只保证烘焙进去的片段。

## 14. 模具库：路线 B 的副产品，不是另一条路（2026-10-26）

用户提出的保底路线——"先做合理的模板再套皮，模板从少到多积累，不断适配更多角色，本地素材库之外还能推到 GitHub 或自建仓库，像大平台那样越滚越大"——和路线 B 是同一件事的两面：两张图的设计已经把**形**（几何用图 → 空白人台）和**皮**（贴图用图 → 贴图）分开，而 §0.1 的真机实验证明光滑人台贴上原画后眼睛准确落位（见「几何头 + 贴图」）。所以每个通过几何检查的部件就是一个**模具**，今晚的几何头就是「大肥鱼·头部模具」，换一张别的角色的贴图用图去贴就是"套皮"。

**模具是什么**：一个部件版本（`kind: 'part'`）加一份元数据 `mould.json`：资产类型、部位（`PartRole` / `PartId`）、风格、归一化包围盒和比例（头高/身高等）、面数与档位、通过了哪些 G 检查（含 G5 眼带 F25 数值）、来源图的 sha256、生成服务与模型、**许可证**（大肥鱼的设定图是 CC BY-NC-SA，派生模具只能非商用并署名；原创角色无此限制）、作者。

**怎么长**：
1. 第三关里部件通过审核 → 「存为模具」（本地资产库，标 `template: true`），零成本。
2. 导出成 bundle（GLB + mould.json + 缩略图），推到仓库——公开仓库的 `moulds/` 目录或单独的模具仓库，一份 `index.json` 做目录；应用后续可以浏览、拉取、按许可证过滤。先按角色积累（"大肥鱼角色模具组"），比例量化到位后才可能跨角色命中。

**怎么适配（量，不猜）**：新角色进来，先按资产类型 + 部位筛，再比设定图量出的比例（C3 / G4 用的同一套包围盒数据）：偏差 ≤ G4 公差（15%）直接套皮（贴图 op，10 积分），偏差大的部位才重新生成这一件（40 + 10），其余照旧。于是"模板路线"与"生成路线"合成一套带判定规则的系统：能复用就复用，复用不了的部位才花积分，经验库顺带记录命中率。

**版权分级（用户 2026-10-26 提出，工程上的保守划分，不是法律意见）**：著作权保护的是表达（发型、脸的画法、服装、鳍、尾巴、配色、名字），比例和风格约定不受保护；去掉头发、服装、配件和脸部画痕的素体人台不再是某个角色，而是一种体型的模具。但模具按**来源**分两级：
- **派生**（从第三方设定图生成，如 CC BY-NC-SA 的大肥鱼）：本地任意使用；公开只能沿用原许可（非商用 + 署名 + 相同方式共享），默认不公开、不商用。
- **原创 / 公共**（用我们自己的通用人台指令生成，如"两头身 Q 版素体人台，不参考任何角色"，只借用量出的比例数字）：许可证由我们定，可进公共模具库。
公共模具一律**去身份化**：头发、服装、配件、脸部画痕不进模具，只留素体；头部模具更保守，公共版只用通用指令生成。元数据必带 `source`（来源图 sha256）、`license`、`tier`（original / derived）。这样"尽可能保留能用的"和"不越界"同时成立。

**落点（第三关之后）**：`PartModel` 加 `template` 标记与 `mould` 元数据（含 `tier`、`license`、`source`）；`library:setPartTemplate`；导出 bundle 的本地任务；仓库索引格式；设置里的模具源（仓库地址列表）。

### 5.x 贴图图的外轮廓线（2026-10-27）

贴图图是线稿上色风格，画师模型会在每个视图的人物最外圈画一圈深色勾线。这圈线不是任何表面的颜色：贴图步骤把视图投影到模型上时，侧视图看得到的表面会被侧视图盖掉，但两腿内侧、腋下这些侧视图看不到的表面只能从正/背视图的轮廓边缘取色，取到的就是勾线 → 顺着腿贯穿的黑带（大肥鱼白袜子内侧，2026-10-27）。

规则：贴图图在去碎块之后、切视图之前先去掉外轮廓勾线（worker 修复 `strip-outline`，`ops/outline.ts`）——只处理与背景通过暗像素相连、粗细在"勾线中位粗细 × 2.5"以内的暗像素，换成往里第一个不更暗的像素的颜色；贴着轮廓的深色部件（头发、腰带、黑鞋，游程更长）整段保留，人物内部的线条不动。几何图本来要求无线条，不处理。提示词同时要求画师模型不画外轮廓线（`KIND_RULES.texture`）。
