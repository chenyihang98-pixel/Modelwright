# 拆件建模（分部件流水线）设计 — 草案

2026-10-25 起草。配合 0.1.11 的极限测试，尚未实现；"路线 A 实测"一节在对照跑完后补。

## 0. 为什么要拆件

- 2026-10-25 的极限测试把 Tripo 开到最高档（H3.1 超清几何 200 万面、8K 贴图、原生 2048 上传），大肥鱼 v5 的外表面细节确实上去了，但**被遮挡的区域不存在**：刘海下面没有眼睛，头发下面没有额头，掀开头发直接是壳的内腔。
- 数据：v1（193,320 面）和 v5（1,887,300 面）都是**一个封闭壳**，开放边 0、连通壳 1（v5 有 4 条非流形边）。这不是破洞，是单图 / 多视图生成的工作方式：只重建照片能看见的最外层。参数开满只会让这层壳更细。
- 人工建模的流程是一个个部件建好再组合：身体完整，衣服头发套在外面，被挡住的地方由人决定。越接近这个流程，问题越有地方修。
- 结论：把"拆件 → 制图 → 审核 → 分件生成 → 组装 → 绑骨"做成 app 内有指标、有闸门、能积累经验的流水线。不预测结果，而是在最便宜的环节测量，花大钱之前让用户看一眼，每次结果记下来。

## 0.1 第二个隐形问题：画上去的线变成了浮雕

白模模式下看 v1 和 v7 的脸（2026-10-25 对比视图）：睫毛是一圈竖起的鳍、瞳孔是同心的凸环、刘海的边缘在额头上刻出沟、嘴是一道槽。这些在原画里是**画出来的**线和明暗，生成模型把它们当成了**几何**。贴图盖上去之后看不出来（"最表面那层完成得不错"），所以是隐形的；它在四个下游环节冒出来：

- 光照一变（Unity 实时光、法线贴图），浮雕投出阴影，脸上出现脏痕。
- 绑骨动画：眼睛是刻死的凸起，不能眨眼、不能换眼神；嘴是槽，张不开；刘海和额头长在一起。
- 重新贴图：`texture_model` 往浮雕上画，瞳孔、睫毛处会出现重影。
- 减面：高频浮雕先碎，脸最先变脏。

v1（标准几何、1024 上传）和 v7（超清几何、原生 2048）都有，超清只是把浮雕刻得更清楚。这不是参数问题，是"用一张图既定形又定色"的工作方式问题。

**路线 B 的对策：每个部件两张图。** `几何用图`：平涂、无线条、无明暗、闭眼或无瞳孔的素面，只负责形体；`贴图用图`：原画细节，只在贴图步骤作为 `texture_prompt` 传入。这正是人工流程里"先雕光滑的形，再画"的分工。配套一项几何检查 **G5 面部浮雕指数**：面部区域法线的高频方差、小尺度凹凸特征计数，超阈值就换几何用图重生成，而不是等贴图盖住。

## 1. 两条路线

| | 路线 A：让 Tripo 自己拆 | 路线 B：我们拆件制图再分件生成 |
|---|---|---|
| 输入 | 现有整身四视图 | 原图 → 每个部件单独一张四视图 |
| 接口 | `generate_parts`（+20）→ 追加贴图；可再 `mesh/segment`（40）+ `mesh/complete`（50 / 快速封口 30） | 每件 `multiview_to_model`（上限档 70）；组装在本地 |
| 控制权 | 怎么拆、补什么全是模型猜 | 每个被遮挡区域由我们的图决定 |
| 积分 | 约 90 | 约 300–650（见 §9） |
| 用途 | 基线与对照；便宜的"自动拆件"档 | 主线 |

路线 A 的结果决定路线 B 的三件事：部件清单的默认模板和 Tripo 的 `part_names` 命名；拆出来的件是封闭壳还是切口面（决定「部件补全」是必经步骤还是按需触发）；追加贴图后每件的贴图质量（决定分件贴图是否可用）。

## 2. 三道闸门：钱越贵的环节闸门越靠前

```
草稿 ──► 闸门一 遮挡分析（0 积分）──► 判定卡：整体 / 分件，两条路线的积分
            │ 用户选分件
            ▼
         分件制图（图像积分，每件 5–20）＋ 自动检查 C1–C6，不达标自动重画 ≤2 次
            │
         闸门二 部件图审核页：通过 / 按备注重画 / 合并 / 删除；全部通过可一键放行
            │ 放行前一分 3D 积分不花
            ▼
         分件生成（每件 30–70）＋ 每件几何检查 G1–G4
            │
         粗组装（本地）＋ 穿插检查 P1–P2
            │
         闸门三 组装审核：三维里看、微调、退回某一件
            │
         整体绑骨 ──► 完成，写入经验库
```

状态机落在资产版本上：`draft → occlusion → sheets_running → sheets_review → parts_running → assembly_review → rigging → done`，任一步可退回。

## 3. 部件模板

规则只有一条：**凡是会遮挡别的部件的东西单独成件；贴身不遮挡的并入；要单独动或单独换的单独成件。**

| 资产类型 | 部件（英文 id，固定） | 说明 |
|---|---|---|
| 人形角色 | `head` 光头含完整五官 · `hair` 含刘海后发 · `body` 内层躯干四肢含贴身衣物 · `outer` 外层服装，可多件（裙、围裙、外套、披风） · `shoes` · `acc_*` 配件（帽、武器、翅膀、尾巴，各一件） | 袜子手套并入 body；发饰默认并入 hair，用户可拆 |
| 生物 / 四足 | `body` · `head`（可选） · `mane` / `tail` / `wings`（有则单独） | 毛发遮挡身体时 mane 单独 |
| 道具 / 载具 / 建筑 | 按可动件拆：`door_*` `wheel_*` `turret` … | 没有可动件就不拆 |

清单由模板给默认值，视觉模型看原图确认哪些存在，用户在判定卡上勾选增删。Tripo `part_names` 到这些 id 的映射等路线 A 实测后定。

## 4. 闸门一：遮挡分析

分两级，一级立刻、零积分；二级可选、只花图像积分。

**一级（规则）**
- 脸被头发挡住超过一成 → 分件（头一歪刘海下面就露出来，正是这次的问题）。
- 有裙子、披风、宽松外套 → 分件（走路时腿和身体必然露出来）。
- 需要单独动或单独换的东西（武器、翅膀、尾巴、帽子） → 分件。
- 道具、建筑等静物，或以上都没有 → 整体生成。
- 一级的"有没有刘海 / 裙子"先由类型模板加用户勾选回答；本地像素启发式（肤色区域与头部框）只做提示，标为弱证据。

**二级（测量）**
- 先只画最关键的两件：`head` 和 `hair`（约 10–40 积分）。
- 脸部被遮挡比例 = 光头图的脸部掩膜 − 整身图正面可见的脸部掩膜，按整身图位置框归一化。
- 超过阈值（初值 10%）即确认分件，这两张图直接进入闸门二，不浪费。

**输出：判定卡** `{ route: 'whole' | 'parts', reasons: [...], hiddenRatio?: number, costs: { whole, parts } }`，默认跟判定走，用户可改。

## 5. 分件制图与自动检查

每件一张 4:1 的四视图设定图，复用现有「四视图设定图」模板和「拆分设定图 2.0」；整身四视图作为参考图一并传入（Seedream 5 / Banana 2 / Banana Pro / chat_image 2.5 都支持多参考图）。

**指令模板**（中英各一份，部件专属片段拼接）：

> 只画这个角色的【部件】，其他部分一律不画。与参考图同一相机、同一 A 姿势、同一比例和位置；正、左、背、右四个视图排成一行；纯白背景、无阴影；物体必须完整，参考图里被挡住的面也要画出来。

部件专属片段：`head`「光头，完整的脸，双眼睁开，不画头发」；`hair`「只画头发，像一顶空心的帽子，不画脸和皮肤」；`body`「穿贴身内层衣物的身体，不画外层服装和鞋」；`outer`「只画这件衣服，保持穿着时的形状，里面不画身体」；`shoes`「只画这双鞋」。

每件固定一个随机种子；重画时把失败的检查项写成一句话追加到指令末尾。

**自动检查**（全部本地，用现有抠图、`splitSheetMask`、`classifyViews`、同侧镜像检测）：

| 编号 | 检查 | 初始阈值 | 失败后 |
|---|---|---|---|
| C1 | 拆出四个视图且顺序可判 | expected = 4，assignViews confident | 重画 |
| C2 | 四视图高度一致 | 高度变异系数 < 3% | 重画 |
| C3 | 轮廓对齐：部件掩膜落在整身掩膜（膨胀 2%）内；部件高度 / 整身高度与模板估计比例一致 | 溢出 < 5%；比例偏差 < 8% | 重画，指令加"按参考图比例" |
| C4 | 部件专属完整性：`head` 肤色占比 > 40% 且上三分之一有两个对称深色块；`hair` 肤色像素 < 2%；`shoes` 高度 < 整身 25% | 见左 | 重画，指令加对应片段 |
| C5 | 背景干净：掩膜连通块 = 4，杂块面积 < 0.5% | 见左 | 重画 |
| C6 | 风格一致：与整身图的色板距离 | 初值待校准，先只警告 | 警告 |

每项输出 通过 / 警告 / 失败 和一句可读理由；失败自动重画最多 2 次，然后交给用户。

**审核页**：整身图在左，部件卡片在右；每张卡片列检查结果，不通过的排最前；按钮：通过、按备注重画、合并到某件、删除；全部通过时显示"一键放行"，旁边写明放行后的 3D 积分。

## 6. 分件生成与几何检查

- 每件走 `multiview_to_3d`，按预设档位（极限：H3.1 超清 + 8K；展示默认：4K；游戏：标准）。贴图在生成时直接出，**不用** `generate_parts`。
- 面数预算按部件面积占比分配，总和不超过档位上限：head 25%、hair 25%、body 20%、outer 20%、shoes 5%、配件 5%。
- 几何检查：G1 开放边 = 0；G2 连通壳 = 1（hair 允许 ≤ 3）；G3 面数在预算内；G4 包围盒长宽比与设定图相差 < 15%。G1 失败的件走「部件补全」（50）或本地快速封口。
- 入库：每件是资产下的子版本，`kind: 'part'`，带 `partId` 和所属「拆件方案」。

## 7. 组装

- **底座**：整身模型。已有就复用；没有就用标准档生成一个白模（20 积分），只做对齐参考。
- **粗放**：每件在正面图和侧面图里的位置框 → 三维包围盒（x 取正面，z 取侧面，y 共用），按角色身高缩放。Tripo 输出是归一化尺寸，每件按设定图算出的尺寸重新缩放。
- **精配**（第二阶段）：对底座上也存在的部件（头发外层、身体），点到面 ICP 对齐。
- **穿插检查**：P1 两两部件之间，采样顶点做奇偶射线测试，统计落在对方内部的比例；P2 部件间最小间距。允许的嵌套：head 在 hair 内、body 在 outer 内、脚在 shoes 内；其余超过 2% 警告，超过 10% 退回。
- 输出一个多网格 GLB，节点按 `partId` 命名，材质按件；引擎需要时再合并。

## 8. 绑骨

整体组装后再绑：Tripo 自动绑骨（多网格 GLB 是否接受，待测）或本地神经元绑定（天然支持多壳）。头发、裙子沿用 0.1.5 裙摆稳定器的 helper 思路。

## 9. 积分模型（单个人形角色、六个部件）

| 环节 | 极限档 | 展示默认档 | 游戏档 |
|---|---|---|---|
| 整身四视图（已有可跳过） | 5–20 | 5–20 | 5–20 |
| 遮挡分析 | 0 | 0 | 0 |
| 部件图六张，含约五成重画 | 45–180 | 45–180 | 45–180 |
| 整身底座（已有可跳过） | 0 | 0 | 20 |
| 分件 3D，每件 × 6 | 70 × 6 = 420 | 40 × 6 = 240 | 30 × 6 = 180 |
| 部件补全，仅对没封闭的件 | 每件 50 | 每件 50 | 每件 50 |
| 绑骨 | 25，或神经元绑定 0 | 25 | 25 |
| **合计** | **约 500–650** | **约 300–450** | **约 250–400** |

闸门二之前只花图像那一段，约 50–200；大头在用户放行之后才花。估算接进现有 `cost.ts` 的逐行估价。

## 10. 经验库与样本集

- 每次运行记录：拆件方案、每项检查的数值与结论、重画次数、积分、每件几何统计、用户每个闸门的决定。存库（`parts_runs` 表）并可导出 JSON 进文档。
- 阈值集中在 `src/shared/data/partsThresholds.ts`，带版本号；§5 §6 §7 的初值是工程判断，样本集跑完后校准。
- 固定样本集六个角色：长发遮脸、裙装、披风、盔甲、四足动物、机甲。两条路线各跑一遍，结果写进验收指南，这就是可以公开的经验。

## 11. 实施阶段与代码落点

- `src/main/core/parts/`：从方案生成图像请求和 3D 请求、串接现有任务流水线、写经验库。

- 资产库：`kind: 'part'` 子版本、拆件方案存储；`cost.ts` 估价行。
- 大肥鱼作为样本一跑通。

**第二阶段**
- ICP 精配、穿插自动修正、接入 `mesh/complete`、用样本集校准阈值、Tripo 多网格绑骨验证。

## 12. 路线 A 实测（2026-10-25）

任务：大肥鱼同一张四视图，H3.1 超清、目标 200 万面、`generate_parts`，追加「贴图 · 极致（8K）」，自动绑骨关闭。整单 21 分钟（生成约 10 分钟含 50 MB 白模下载，贴图约 10 分钟含 66 MB 下载，本地后处理 1 分钟），实扣 90 积分（60 + 30），余额 635 → 545。结果：v7 分部件白模、v8 贴图、v9 后处理（LOD0–2，104 MB）。

**拆成 15 件，名字全是 `tripo_part_0…14`，没有语义名。** 每件一个连通壳、0 非流形边，但**每件都有开放边**：它们是同一个外壳按部位切开的切口面，不是各自封闭的物体。

|---|---|---|---|---|
| part_0 | 866,606 | 2,960 | 0.445 × 0.735 × 0.553，y −0.245 → 0.49 | **头发 + 头 + 脸 + 躯干上半身，一整块** |
| part_1 | 484,874 | 2,910 | 0.383 × 0.432 × 0.473，y −0.386 → 0.046 | 裙子 + 围裙 + 下半身 |
| part_2 / 12 | 55,218 / 53,836 | 1,042 / 1,044 | 0.16 × 0.26 × 0.13–0.15，左右镜像 | 两条腿 |
| part_3 | 85,264 | 594 | 0.28 × 0.26 × 0.435，z −0.353 → 0.082 | 尾巴 |
| part_4 / 11 | 90,388 / 72,402 | 200 / 384 | 0.09 × 0.21–0.23 × 0.19–0.22，左右镜像 | 两条手臂 / 袖子 |
| part_5 / 8 | 45,217 / 45,251 | 221 / 237 | 0.12 × 0.15 × 0.08，y 到 −0.49，左右镜像 | 两只鞋 |
| part_6 / 7 | 33,644 / 31,561 | 586 / 573 | 0.14 × 0.15 × 0.17，头两侧，左右镜像 | 头两侧的鱼鳍 / 耳 |
| part_9 | 23,868 | 296 | 0.06 × 0.08 × 0.11，胸前 | 胸前蝴蝶结 |

贴图：15 个材质、15 张 8K 贴图（每件一张），v8 文件 66 MB。

**对路线 B 的三个回答**
1. 命名：Tripo 不给语义名，`part_names` 只能传 `tripo_part_N`；部件清单和命名必须由我们定（模板 + 位置推断）。
2. 封闭性：没有一件是封闭的，**头发没有和脸分开**（part_0 把头发、脸、躯干切成一块）。所以路线 A 即使再接「部件补全」，补的也是这一整块的切口，刘海下的眼睛、头发下的额头仍然不会出现。被遮挡区域的问题，自动拆件解决不了。
3. 贴图：按件分贴图可行，但 15 张 8K 对一个角色是浪费；路线 B 应按面积分配贴图尺寸。

**反过来，路线 A 有两个意外收获**：眼睛被切成独立的两件（眼球换贴图、做眨眼动画有了入口）；鞋、尾巴、手臂、鱼鳍都干净地分开了，这些可动件的切口本身就是绑骨和物理的天然分界。

**结论：** 自动拆件是"分割"，不是"分件建模"。它能把可动的末端切开，切不开贴在一起的头发和脸，也补不出照片里没有的面。要让被遮挡的区域存在，只有路线 B：每个部件有自己的四视图，各自生成成封闭物体，再组装。

## 13. 未决问题

- Tripo 自动绑骨是否接受多网格 GLB。
- 图像模型能否稳定画出"只有头发"和"光头"，首轮样本见分晓。
- 每件都上 8K 贴图是否浪费，可能按面积分配贴图尺寸。
- 大肥鱼设定图为 CC BY-NC-SA，样本集公开时注意署名与非商用。
