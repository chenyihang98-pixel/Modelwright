文字或图片进，游戏可用的模型出——本地完成减面、LOD、碰撞体、轴心与尺寸，再直接送进你的 Unity 工程。生成本身由云端服务完成（你自己的 API 密钥），本机不需要下载任何大模型权重；换一台电脑，装上应用、填入密钥即可继续工作。

> 当前版本 **0.1.27**（2026-11-10）：重新发送角色时，Unity 插件（0.1.32）只清理确实没人用的网格副本，旧插件会误删时应用先拦下、不写入；动作设计台的动作烘焙、导出后与预览一致，模型自带的动作保持原样；Unity 试玩里走跑切换对齐步伐。各版本的改动见 [RELEASE-NOTES.md](RELEASE-NOTES.md)，验证情况见文末「验证情况与已知限制」。

### 自动更新

从 0.1.1 起，**安装版**启动几秒后会到本仓库的 Releases 检查新版本：有新版本就在后台下载，下载完在窗口顶部提示「重启后生效」，也会在下次退出时自动安装。可以在「设置 → 语言与关于」里关闭自动检查，或手动点「检查更新」。更新包同样来自 GitHub Releases，下载慢或失败时应用只记录日志，不会打扰你。便携版和 zip 不会自动更新，请回到 Releases 下载新版本。0.1.0 还没有这个功能，所以从 0.1.0 升级到 0.1.1 需要手动下载安装一次（安装到原目录即可，资产库和设置都会保留）。

## 能做什么

| 环节 | 内容 |
|---|---|
| 准备输入 | 图片自动抠图、构图、尺寸适配；拆分三视图 / 四视图设定图（任意行列网格、标签、特写框、地面线都能处理，自动判断正面 / 侧面 / 背面归位，相对视图镜像了会提醒并一键修复）；一张正面图让概念图服务画出姿势一致的四视图再自动拆分；提示词优化（可接大模型，也可离线模板）；可先出概念图再生成 3D；批量：一行一个描述，逐行自动识别资产类型并给出引擎名称，检查后一次确认、一起提交 |
| 预设 | 14 种资产类型 × 8 种目标平台 × 5 种风格，自动换算面数预算、贴图尺寸、LOD、碰撞体、轴心与真实尺寸；「展示 / 影视级」一档不按实时预算，直接要服务商的最高几何精度和 4K 贴图 |
| 命名 | 每个资产有显示名称（中文即可）和引擎名称（ASCII）。中文名称自动转写为拼音：木桶 → `MuTong`、骑士长剑 → `QiShiChangJian`；提交前可以改。Unity 里的文件夹、模型、贴图、预制体都按引擎名称和「设置 → 命名规范」命名 |
| 预检 | 花积分之前逐项检查图片、提示词、参数、费用与余额，能自动修的直接修 |
| 生成 | Tripo（V3，中国区 / 国际区两栏密钥，各自测试、各自看余额）、Meshy、腾讯混元生 3D；内置离线「演示服务」，无需密钥即可体验完整流程 |
| 后处理（本地、免费） | 减面到预算、生成 LOD 链、碰撞体、轴心与尺寸校正、Unity 贴图打包；在「资产」页可以多选后批量处理 |
| 验收 | 三道关卡逐项验收并给出 A–D 等级：生成后、本地后处理后、导入 Unity 后（由插件回传的结果判定材质、预制体、包围盒、LOD、碰撞体），每一项都说明问题和处理办法 |
| 资产库 | 版本历史、搜索（支持中文）、筛选、回收站、导出 GLB / OBJ / STL / PLY |
| 动作 | 动作设计台按关节角色给能识别出关节的骨架（标准人形、四足、神经元绑定的部件骨架）做待机 / 走路 / 奔跑 / 跳跃 / 挥手 / 鞠躬 / 部位摆动（人形走路有落脚与两骨 IK，膝盖朝前弯，步幅按这副骨架能走的范围核对）；导入 Mixamo 等动作文件按关节角色重定向；已有绑骨件一键「补全基础动作（本地）」；烘焙进 GLB；试机场与靶场直接试玩，按步速配速（支撑脚滑动大幅减少，但没有完整的脚底 IK，不保证零滑步） |
| 蒙皮 | 「权重整理」：拼装角色的尾巴整体跟骨盆、裙摆加辅助骨；「接缝权重统一」：只修动作中真的裂开的同一表面接缝，存为新版本，不焊接、不改几何 |
| 进引擎 | 一键写入 Unity 工程的 `Assets/Modelwright/`；装了插件会自动建材质、预制体（含 LODGroup 与碰撞体）并放进场景；导入时保留模型自带的蒙皮；在应用里做过「权重整理」的裙装角色带着裙摆辅助骨，跑动时裙子不再跟着大腿翻起 |
| 任务队列 | 生成、后处理、发送都在后台排队执行；一次批量生成、批量后处理或批量发送在队列里是一组，可以整组停止、继续或重试失败项；应用重启后队列照常恢复 |

界面为简体中文，可在「设置 → 语言与关于」切换为英文。

## 第一次使用

1. 打开应用会进入引导：选择生成服务。还没有密钥就选 **演示（离线）**——演示服务完全离线，返回的是内置的示例模型（不是按你的描述生成的，结果上带「示例」标记），用来走通整个流程：预设、预检、后处理、验收、送进 Unity。
2. （可选）连接 Unity：应用会列出 Unity Hub / 团结 Hub 里的工程，也可以粘贴工程的完整路径；点「安装插件」。
3. 进入首页，把一张图片拖进「拖入图片，一键生成并送进 Unity」，或者输入一句话描述。
4. 结果会出现在首页和「资产」页；在「工作台」里可以查看网格、贴图、骨骼，做后处理、导出或发送到 Unity。

### 配置真实的生成服务

设置 → 生成服务。密钥只写入、不回显，使用 Windows 的系统加密保存在本机，界面、日志和任务记录里都不会出现密钥原文。

| 服务 | 获取密钥 | 说明 |
|---|---|---|
| Tripo | 中国区 <https://developers.tripo3d.com> ／ 国际区 <https://developers.tripo3d.ai> | 推荐。两个区是两个独立账号、积分不互通，设置里各有一栏；填错栏时「测试」会提示应填到哪一栏 |
| Meshy | <https://www.meshy.ai/developers/keys> | 会员制：先订阅 Pro（或更高）会员，API 才可用；免费账号创建的密钥会被拒绝 |
| 腾讯混元生 3D（TokenHub） | <https://console.cloud.tencent.com/tokenhub/apikey> | 腾讯云 TokenHub：先在「启用管理」为 HY-3D 系列模型领取免费额度或开通后付费（按模型开通），再在「API Key 管理」创建 sk- 开头的 Key（地域选广州，访问范围「全部模型和服务」）。应用内的「接入指引」带截图 |

可选：设置 → 概念图与提示词，配置概念图服务（兼容 OpenAI 接口的各家、Tripo、Gemini）和提示词大模型（Anthropic，或兼容 OpenAI 接口的 DeepSeek / 通义 / 智谱 / 硅基流动 / Moonshot / OpenRouter / Ollama 等）。不配置也能用，只是没有概念图和智能优化。

**网络**：设置 → 网络代理，默认跟随系统代理（Clash、v2rayN 的「系统代理」模式可直接使用）。「测试连接」会逐个探测各服务地址。

**费用**：生成消耗的是你在各服务商账户里的积分。

- 提交前显示预计消耗；超过你设定的阈值必须确认，批量提交和失败任务的「重试」也一样（重试按钮上直接写着预计消耗）。
- 会计费的请求绝不自动重发。提交后没有得到服务商答复的任务（可能已经计费）会在首页顶部和「任务」上醒目提示，由你决定采用、重新提交还是放弃。
- 服务商不支持取消已经开始的云端任务时，「停止等待」之前界面会说明：它仍会在云端继续运行，并且可能照常计费。
- 金额只在应用有依据时才显示：Tripo 国际区按 $0.01 / 积分估算、混元中国站按 ¥0.12 / 积分估算，并注明是估算；Tripo 中国区、混元国际站和自定义接口地址只显示积分，不折算金额。

## 连接 Unity

支持 Unity 2022.3 LTS、团结引擎 1.x、Unity 6；Built-in / URP / HDRP。

在「引擎」页添加工程并点「安装插件」（插件是嵌入式包 `Packages/com.modelwright.bridge`，只在编辑器里运行，不进构建产物）。发送之后得到什么，取决于工程当时的状态：

| 工程状态 | 结果 |
|---|---|
| 已装插件，编辑器开着（已连接） | 立即导入：按渲染管线生成材质，做好带 LOD 和碰撞体的预制体，放进场景，并把导入结果（材质、预制体、包围盒、LOD、碰撞体）回传给桌面端，验收清单的「Unity 内」一关据此判定 |
| 已装插件，编辑器没开 | 文件先写进工程，下次打开或刷新时由插件完整导入（不放进场景，没有回执） |
| 没装插件 | 只写入文件到 `Assets/Modelwright/`，由 Unity 按默认方式导入，没有预制体 |

GLB 需要 glTF 导入器（glTFast）：工程里没有时，应用会让你选择「安装 glTFast（推荐）／云端转成 FBX／本地导出 OBJ」。带骨骼的模型在装了 glTFast 的工程里可以直接按 GLB 发送（Generic 骨架，不花积分）；需要 Humanoid 重定向时再选云端转 FBX。带动作的角色发送后，插件会在预制体旁生成一个 Animator 控制器（每个动作一个状态，idle 为默认），放进场景按 Play 就会动；你自己换的控制器不会被覆盖。桌面端和插件之间只通过本机回环地址通信，数据不离开这台电脑。

## 数据保存在哪里

| 内容 | 安装版 | 便携版（单文件 exe） | zip 版 + `portable.flag` |
|---|---|---|---|
| 资产库（模型、贴图、缩略图、输入图片） | `文档\Modelwright` | `Modelwright-Data\Library` | `data\Library` |
| 设置、密钥（已加密）、数据库 | `%APPDATA%\Modelwright\data` | `Modelwright-Data\data` | `data\data` |
| 日志 | `%APPDATA%\Modelwright\logs\main.log` | `Modelwright-Data\logs\main.log` | `data\logs\main.log` |
| 临时文件（每次启动清空） | `%APPDATA%\Modelwright\temp` | `Modelwright-Data\temp` | `data\temp` |
| 界面缓存（内置浏览器引擎） | `%APPDATA%\Modelwright` 其余 | `Modelwright-Data` 其余 | `data` 其余 |
| 更新器缓存（下载的安装包） | `%LOCALAPPDATA%\modelwright-updater` | 无 | 无 |
| Unity 桥接文件（运行时才有） | `%USERPROFILE%\.modelwright\bridge.json` | 同左 | 同左 |

「设置 → 资产库 → 存储位置」把这七处逐一列出（路径、大小、可打开），可以一键清理缓存，也可以输入 ERASE 删除本机全部数据并退出。安装版的卸载程序会自动清掉更新器缓存、桥接目录和旧的临时目录，并问两次：是否同时删除应用数据（设置、密钥、数据库、缓存），是否同时删除资产库。应用不会往这七处以外的地方写文件（发送到 Unity 工程、导出到你选的目录除外）。

资产库位置可在「设置 → 资产库」更改或整体迁移；日志可以在「设置 → 语言与关于」里直接打开。密钥用 Windows 当前账户加密：把便携版拿到另一台电脑（或另一个 Windows 账户）后，需要重新填一次密钥，其余数据照常可用。卸载安装版不会删除资产库和设置。

## 隐私与安全

- 没有自己的服务器：应用不收集、不上传你的数据；只有在你主动发起生成等操作时，相关内容才会发送给你选定的服务商。
- 密钥只存在本机，由操作系统加密；界面层永远拿不到密钥，也不直接访问互联网。
- 应用代码带完整性校验：安装目录里的程序文件被改动后应用会拒绝启动。
- 随包附带全部第三方组件的许可证全文（`THIRD-PARTY-NOTICES.txt`，也可在「设置 → 语言与关于 → 第三方许可」查看）。
- 程序未签名；请只从本页的 Releases 下载，并核对 SHA-256。

**已知限制**

- 仅支持 Windows。只完整支持 Unity；Unreal / Godot / Blender 只预留了位置。
- 手动「后处理」面板不处理带骨骼的模型；带骨骼的 GLB 在生成后的自动链里（要了本地后处理时）只在外层节点上整体缩放、转正朝向（人形转到面向 +Z）并加碰撞体，不减面、不做 LOD；烘焙动作只把动作写进去，不再缩放、转正或加碰撞体；只有 FBX 的版本不做本地后处理，也不能直接烘焙动作（Tripo 上四边面 + 绑骨只交回 FBX）——先在动作设计台点「补全基础动作（本地）」在本机转成 GLB，再烘焙、按 GLB 发送（这条转换在混元 FBX 上实测过，Tripo 的 FBX 没有逐一测）；KTX2 压缩贴图无法在本地缩放。
- 本地抠图用的是小模型（u2netp），背景复杂时边缘可能带残留，图片处理窗口里可以用擦除 / 恢复画笔修正。
- 引擎名称的拼音转写按词读多音字（长剑读 Chang、重甲读 Zhong），生僻词可能读错；超过六个音节的中文描述只取末尾六个音节。名称在提交前可见、可改。
- 批量里的资产类型按关键词离线识别（武器、载具、建筑、角色、植物等）；「木桶」「宝箱」这类没有特征词的道具沿用面板当前的资产类型，审核表顶部会写明有几条是这样，可以逐行或一键统一修改。
- 演示服务返回的是内置示例模型，与你的描述无关；它只用于体验流程。
- 接缝权重统一修好的接缝点按两侧骨平均跟随，是拉伸而不是平滑过渡；不到门槛（默认 1 mm）的开缝保留不动；连到开放边缘（裙摆、袖口等开口）或非流形边的整条接缝不修。
- 裙摆保形没有布料碰撞（0.1.7 起前片随抬腿掀起，走路不再穿出，但奔跑的极限帧膝盖仍可能擦到裙摆），不处理头发。0.1.26 起 Unity 插件（0.1.29）不再自动给模型找裙子、加辅助骨：裙装角色先在应用里做「权重整理」；旧的自动检测只在交付说明文件写 `legacy` 时运行，界面没有开关。
- 神经元绑定的部件只从身体上长一层（手指、头上的耳朵并进所在部件）；紧贴身体的手臂、裙子里的腿几何上分不出来（面板会按资产类型提示）；动作是程序化摆动不是步态，脚不贴地；细于一格体素的部件会被忽略（可选「精细 96」）；既没有腿也没有粗头的模型朝向按 +Z 假定。内置试机场没有物理引擎（木箱是方块碰撞，没有坡和台阶）；真实的非人形生成模型还没有拿到手测；Unity 试机场已在真实编辑器的 Play 模式里用真实键盘走过（插件 0.1.27、旧输入管理器的工程，最终混元人形）；只开新输入系统的工程读不到键盘，演示只会自动绕圈；Mixamo 的真实下载文件已在 0.1.16 实测（14 条步枪动作导到 Tripo 绑骨角色，见上方 0.1.16 一条）。
- 动作设计台的模板是程序化动作，不是动作捕捉：人形走路有落脚和两骨 IK，但步幅、屈膝比真人小，关键帧之间有毫米级插值偏差，蹬地时前掌会压进地面几毫米，没有转身、坡道和全身 IK；想要更真的动作仍走服务商动作库或外部 FBX；镜像骨架不在支持范围（动作设计台会提示）；FBX 版本的原文件不会被就地改写：设计或导入的动作要带出应用，用动作面板的「导出带动作的 GLB 文件…」（当前模型加已保存的动作烘焙成一个 GLB，可再发送到 Unity）；映射依赖"身体大致直立、左右对称"，躺着的、单腿的、多头的骨架需要手动修正。
- 慢跑（动作设计台里手动选的修订 6）还不是默认基础动作：只在一个两只脚静止等高的人形上逐项核对过；应用试机场里停下时有一帧身体轻微下顿；自带 Running 的角色在 Unity 试玩里从站立起跑 / 停下仍多陷 2.8 / 5.3 mm，跑转走有一帧骨盆变化略超验收线；两只脚静止不等高、鞋尖很长的模型跑起来一只脚很少着地、鞋尖会滑。模型自带的、只给部分关节打关键帧的动作，在应用视口里按绑定姿势补默认值，个别模型会与导出文件和引擎里差几毫米（烘焙和导出按原文件）。
- 极限测试只跑了一个角色、每轮一次，定的是基线不是规则；被遮挡区域不存在和"画上去的线变成浮雕"（睫毛成鳍、瞳孔成凸环、刘海在额头刻沟）这两件事这一版只是查清了（拆件建模当时只有设计草案，0.1.12 起有了第一阶段，见下一条），「部件补全」接口还没接入；8K 贴图与 200 万面的结果文件很大（59 MB / 104 MB），Tripo CDN 慢时一单要 20 分钟。
- 拆件建模只跑了一个角色（大肥鱼）：阈值是初值；组装的固定规则（§7c）给的是起点，头发在后脑仍有空隙、尾巴根藏在裙后，最后要在手动组装面板里摆；穿插检查、组装后减面、对组装版绑骨、部件补全（Tripo mesh/complete）、C3 / C6 检查、模具的导出和仓库都还没有。"只画一对鳍"这类小附件的部件图图像模型画不好（五次都带头），已并入头发。中国区的图像任务跑 5 分钟会被服务端判失败，部件图请走国际区。
- 回退只有页面级；任务抽屉开着时在页面上按 Esc 不回退（沿用抽屉的既定行为）；离开守卫接了动作映射、密钥输入框和手动组装三处草稿。
- 文件夹只有一级、一个资产只属一个夹；动作设计台的模板 / 滑杆 / 名称不进撤销历史；「删除本机全部数据」清不掉正在被占用的文件时会留下并记录；静默卸载一律保留数据。
- 面部平滑填平处的边缘还有些毛糙；落在肤色范围内的腮红、胡须会被当成皮肤不处理；深肤色角色暂不识别。火山方舟 Seedream 的模型 ID 需与你账号里开通的一致，不一致会返回 404，设置里可以手动填。
- 手动代理 + 用户名密码 + 明文 http 接口这一种组合下，代理刚切换后的第一个计费请求在极端情况下可能被发送两次（各真实服务都是 https，不受影响）。
